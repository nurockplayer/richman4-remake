# 開局與日期規則證據

來源為擁有者本機兩版 `rich4.exe`、原作說明書，以及 [mytbk/rich4](https://github.com/mytbk/rich4/tree/54ff26750e7e7f585da6fe68c4e8972cd22ed509) 的反組譯行為研究。只記錄格式與行為，不複製該專案的實作或原作素材。

## 開局表

Game 執行檔的三個完整 little-endian u32 表位於 `0x69640`、`0x69694`、`0x696ac`；MultiverseJourney 對應 `0x6b194`、`0x6b1e8`、`0x6b200`，兩版數值相同。

- 總資金：300000、200000、100000、50000、30000、10000；預設索引 1。
- 期限：0、730、365、182、91、30 天，0 表示不限。
- 財富倍率：0、100、50、10、5、3，0 表示不設目標。
- `csrc/game_init.c` 的開局流程將真人現金與存款各分一半；AI 使用所選角色的 `init_cash_ratio`，其餘作存款。
- 已直接核對兩版執行檔的 12×104-byte 角色表（Game `0x7b22c`、MultiverseJourney `0x7ce0c`）：record `+19` 為 0–11 角色 ID，`+25` 現金比例依序為 50、40、70、60、40、70、50、40、60、50、55、80。經 PE section 映射與 CP950 解碼的姓名依序為約翰喬、沙隆巴斯、忍太郎、錢夫人、阿土伯、莎拉公主、宮本寶藏、糖糖、烏咪、孫小美、小丹尼、金貝貝。

Game SHA-256：`110b29f9d2fadcff3836eb69ec380aa264951859c90955da6e11158d2f956a13`。
MultiverseJourney SHA-256：`50cb24bbbd86353e26127e8e89e891c437984655d338a32f1458a3b79596219f`。

## 日期與結算

- `asm/rich4_date_utils.asm`：年月日實際使用不同月長；年份整除 4 即閏年，包括 2100。星期以 1998-01-01 星期四為基準。
- `asm/rich4_player_core_actions.asm` 的 `fcn_0041cf67`：日期先加一天、已過天數加一，再呼叫 `fcn_0041d89e` 判定期限／目標；其後才更新價格、事件與月底結算。
- `fcn_0041d89e`：逐一比較仍在局內玩家的淨資產，只在嚴格大於目前最大值時替換人選。因此正淨資產平手保留玩家順序較前者。期限判定為已過天數大於或等於設定；財富目標為最大淨資產大於或等於目標。兩者皆 0 時不啟用此結束條件。
- `asm/rich4_calculate_player_wealth.asm`：現金＋存款－貸款＋股票市值＋住宅／商業地的地價與建築價值。股票運算採截斷；原版浮點捨入與目前整數股價的差異須在股票還原時另外處理。
- 日期增量回傳「換月」後，`fcn_00439bfa` 顯示月底結算。`fcn_00437e61` 的 `loc_00438218` 前，無貸款玩家的存款乘 1.1 並截斷；有貸款不領存款利息。對照常數 `0x464e88` 為 double 1.1、`0x464ea0` 為 double 0.1。
- `asm/rich4_config_file.c`／`rich4_getdate.c` 會讀本機日期。模擬核心不得自行讀取時鐘；UI 選定起始日期後將其存入對局，測試使用固定日期。
- 模擬日期的可表示範圍是 1998-01-01 至 9999-12-31。到達 `9999-12-31` 後若下一日無法表示，核心直接以 `calendar_limit` 作終局結算，不增加 `day` 或 `elapsed`，並在 `game_over` 事件標記 `calendar_boundary`；這是實作邊界，不是原作另有一個日期勝負條件。
- v3 存檔會先嚴格確認年月日是有限的整數形狀，再將 JSON 解析後的整數／浮點數欄位逐欄正規化比較；因此 UI 的 `JSON.stringify`、`JSON.parse_string` 與實際 `user://richman4_save.json` 路徑可安全往返。v3 期限／目標結算只有正淨資產才產生 winner；正資產平手仍依玩家順序保留，全部非正時維持進行並讓 winner 保持 `-1`。只有 `calendar_limit` 終局允許無 winner。既有 v1／v2 的存檔與淘汰結算路徑不改變。
- 月底利息透過模擬核心既有的銀行扣款 helper，銀行現金下限為零；原始銀行的資產／資金並非本模擬玩家，這個下限是存檔可驗證性的模擬資金政策，不能解讀為已完整還原原版銀行資產行為。

本票的實作與驗證狀態以 active PR 為準；上列來源不等於全部系統已還原。
