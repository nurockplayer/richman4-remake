## 開始與底價

卡片只能由目前玩家在自己的當前節點發起，目標必須是住宅或設施，且不要求目標屬於
施卡者。住宅來源型別為 `2001..3999`，設施來源型別為 `4001..5999`；來源物件身分、
節點與設施多入口也會在開始及讀檔時重新核對。無效目標與開始前取消都保留卡片和其
餘狀態。

底價為：

```text
trunc(base_land_price * (1 + building_level * 0.5)) * price_index
```

截斷發生在物價指數相乘之前。每次可加價 `100`、`500`、`1000`、`5000` 或 `10000`，
且新報價不能超過當前出價者的現金。

## 參與者與回合

參與列依玩家 ID 遞增。施卡者與當前地主都保留列；其他玩家若現金不大於底價、已
住院／入獄或處於睡眠狀態，便不列入。所有列仍須是存活且未破產的玩家。第一位列中
玩家先回應；出價者成為目前最高出價者，下一輪跳過他。通過會退出拍賣，回合繼續依
遞增 ID 跳過已退出者與最高出價者。

拍賣待回應時保留原本的 `phase` 與 `current_player`，並禁止擲骰、選路、其他卡片、
道具及結束回合。關閉回應視窗只會稍後恢復視窗，不會取消拍賣或改變目標。沒有人
成功出價時流標；其他玩家都退出後，已存在的最高出價者直接成交，不要求他再次加價。

## 成交與流標

卡片在待回應期間留在施卡者手上，只有終端成交或流標時消耗一次。成交時由最高出價
者支付當前出價的現金，款項加入施卡者的存款，並同步加入 `bank.deposits` 聚合值與
`bank.cash`。原地主不直接收款；即使最高出價者本來就是地主，也照常支付並完成成交。
成交保留住宅／設施的等級、型別與其他建物狀態，只更新所有權；設施的每個入口會同步
更新。流標清除所有權，但保留等級、型別、建物與其他設施狀態。

成交前會檢查出價者現金、施卡者存款餘額、銀行存款聚合值及銀行現金的上限。各項
存款／現金上限為 `1e12`；容量不足時拒絕這次加價而仍允許退出，避免留下無法結束的
拍賣。

## 存檔與 AI

`pending_auction` 是可省略的頂層欄位；存在時恰有以下八個欄位：

```text
caster_id, node_id, opening_bid, current_bid,
highest_bidder_id, bidder_id, participants, withdrawn
```

`participants` 與 `withdrawn` 都是排序且不重複的玩家 ID 陣列，後者必須是前者的子集。
初始 `current_bid` 等於 `opening_bid`、`highest_bidder_id` 為 `-1`；施卡者仍是目前
玩家並持有保留中的卡片。不新增存檔版本、歷史玩法分支、保留旗標或出價逐筆 transcript。
讀檔會驗證目標、玩家、回合、參與者、出價及上述四項容量界線，合法 JSON 可繼續回應。

`run_ai_turn()` 由目前出價者的控制類型決定行動，即使施卡者是另一種控制類型也一樣。
AI 使用可重播的保守 fallback：在
`min(cash, 2 * opening_bid, caster_deposit_headroom, bank_deposits_headroom,
bank_cash_headroom)` 內每次加 `100`，否則退出；此策略不使用 RNG，也不宣稱等同原版
精確估值或計時器。

## UI 與驗證

背包的「拍賣」卡會開啟目前出價者回應視窗，顯示目標、底價、目前出價、施卡者與目前
出價者，提供五種加價按鈕及「退出拍賣」。真人只可回應真人出價者；AI 出價者由既有
AI 回合接續，輪到真人時保留視窗與拍賣狀態。

拍賣的 focused checks 為：

```text
tests/auctions_flow.gd
tests/auctions_save.gd
tests/auctions_ui.gd
```

上述測試使用合法 v13 有限供給 fixture，涵蓋住宅／設施、各種所有權、流標、成交金流、
容量拒絕、嚴格待回應存檔、JSON 繼續及背包／視窗操作。AI 精確估值、來源額外刷新
helper `0x40a4e1` 與原版完整動畫、台詞、音效仍屬 Unknown；本批不據此擴張考古範圍。
