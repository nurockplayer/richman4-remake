# 原作企業與十二股市場

企業能力由來源 catalog 的十二個股票列與企業關聯啟用，使用 v7 存檔。
缺少完整資料的舊 catalog 繼續使用既有版本；v1–v6 存檔不會自動轉成企業遊局。
來源為擁有者本機的 Game／MultiverseJourney 執行檔、地圖資料與手冊 pp.16–17。
原始資料、反組譯與衍生快取均留在本機。

## 股份與交易

- 每檔一萬股；企業初始庫存為一萬減來源市場供應。企業與股票以來源列索引連接，
  不以名稱猜配對。股票列的初始 template flag 與執行時企業 ID 分開保留。
- 市場買賣使用銀行存款，交易金額為浮點單價乘股數後朝零取整。市場供應與每回合
  可買額度同時變動。每位玩家開始回合重設額度：供應不超過一千時全部可買，
  否則按來源 10–29.99% 範圍取整。
- 到訪企業可以現金按 `int(stock_value / 10000)` 購買企業庫存，整次造訪合計
  最多一千股。發售所得不進入企業本月／累積盈餘，也不虛構為銀行收入。
- 最大持股者取得經營權；同額保留現任，無現任時採玩家順序。沒有人持股時無經營者。
- 破產股份回到市場與當回合供應，按市價計算的變現金額進入公共獎金池。
  既有地產拍賣仍使用明確標記的暫定分配流程。

## 股價與紅黑卡

每日先更新日曆、倒數停牌／事件狀態，再處理開市股價。週日與全市場停市不更新
價格或歷史；星期日仍會消耗狀態天數。全市場停市最後一天使用到期標記，隔日才開市。
目前 catalog 未匯入額外節慶休市表，不能宣稱已重現原作全部假日。

一般變動率由前日動量、全市場 shock 與個股 shock × 波動係數構成，依企業面額
或未連結股票的初始價套用均值回歸，最後限於 ±10%。候選價格決定 tick：
小於 5／15／50／150 的級距分別為 0.01／0.05／0.1／0.5，其餘為 1。
捨入的是價格差額，方向朝零；股價限制在 1–9999。

紅卡寫入事件 `0x20`，黑卡寫入 `0x02`，立即從該日基準價重算 ±10%，覆寫目前
歷史槽。重複同色只重設效果，不重複複利；反向卡覆寫事件並從同一基準重算。
下一個 daily sweep 先倒數，再由剩餘事件強制漲跌。真人開市時可對停牌股出牌，
AI 選股會排除停牌股，保留已核對的來源差異。

重製採可儲存的 deterministic RNG，無法重現原作 `GetTickCount` 重新播種的軌跡。
市場動量／shock／波動係數採來源儲存的單精度數值；價格以分為單位正規化，讀檔
也恢復相同精度，防止 JSON 解析末位差異影響續玩。這不等同原作 x87 浮點逐步軌跡。
歷史保留最近 144 個開市更新值；呈現採依序追加的陣列，並非原作圖表 UI 的逐像素重現。

## 企業服務

無經營者時不收服務費；經營者本人通常免費。已接入的分支如下：

| 來源 type | 行為 |
| --- | --- |
| 3 | 收費參數 × 已經過日數；不乘物價指數。新局日數從 0 起算。 |
| 4 | 承保天數由 5、3、30、20、15、10 中選取；非經營者付天數 × 收費參數 × 物價指數。 |
| 5／6 | 摩托車或汽車付 700／500 × 本次骰子總點數 × 物價指數；汽車再乘 2，步行不收費。 |
| 11 | 選造訪玩家自己尚未滿級的住宅／設施。非經營者升一級、按目標地價 × 物價指數收費；經營者免費升最多兩級。無目標的非經營者付 1000 × 物價指數。 |
| 12 | 收費參數 × 本次骰子總點數 × 物價指數。 |

企業付款入口套用財神／窮神費率，實際收到的款項同時進入本月與累積盈餘。
建設公司的選擇先完成，再繼續股份交易或結束回合；研究所目標仍不開放，空設施
可選目前已實作類型。企業建設不套用一般投資的衰神禁令或福神額外建造。

保險的住院理賠為新增住院日數 × 2000 × 物價指數，支付給受保玩家的現金，
由第一間 type 4 企業扣除兩種盈餘。理賠不消耗保險，也不按剩餘承保天數打折；
天數到 1 的下一次更新保留當日有效標記，再下一天清除。現已連接惡犬住院；
尚未實作的其他住院／入獄事件不能算作已驗證。

銀行與點券商店保留既有事件服務。旅館 type 2 的手冊住宿描述與已觀測 default
分支不同，其他特殊企業分支仍待整體遊戲後續工作，沒有用猜測補成來源定論。

## 分紅、存檔與驗證

每月十五日以所有存活玩家實際持股總數為分母，分配本月盈餘；不是除以一萬。
每位玩家分配額朝零取整，餘數不另行轉入銀行。有人持股時結算後清零本月盈餘，
無人持股則保留；累積盈餘不變。虧損先扣存款再扣現金，不足時破產。
畫面平均盈餘以月界線次數計算，尚未跨月時顯示累積盈餘。

v7 驗證十二股完整性、雙向企業連結、股份守恆、持股經營權、價格鏡像、歷史尾值、
合法數值型別，以及待處理建設服務與目前玩家／位置一致。拒絕資料不得在型別比較
中拋錯後誤當成功。極端數值超過存檔帳務上限的服務會明確拒絕，這是重製的保護界線。

一致性及最終原生套件操作另記於該次 PR；本頁不把較早測試冒稱為後續 HEAD 的證據。
