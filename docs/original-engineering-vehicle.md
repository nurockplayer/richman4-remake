# 工程車

工程車是來源 ID 12 的研究工具。它已存在於道具目錄與研究產物，本批次接通其使用、期限、落點拆屋及人類／AI操作；不新增存檔版本或歷史玩法分支。

## 已確認的行為

來源入口保存先前載具與選定骰數，將載具模式設為 `0x1f`、骰數設為一，消耗一個工程車。原本裝備的機車／汽車退回背包。來源 `41cca3` 在該玩家的 incoming turn admission 將模式減四；第七次到期時，若背包仍有先前載具就重新裝備並恢復骰數，否則改為步行。其他玩家進入回合不倒數；仍保有此模式的休養回合也計入期限。

`448a7e` 的已確認呼叫點位於落點結算尾端（`41b096`，在神明土地效果之後）與特殊重新進入流程（`418f78`），普通逐步移動沒有此呼叫。非自己所有且已建成的住宅或設施會排入清除建物事件；未擁有但有建物也符合條件。事件沿 `40ab4a(currentnode, 2)` 清除建物而保留所有權。因此不能僅因為道具名稱而把每個經過格都拆除。

一般機車／汽車使用入口可以取代工程車；提前改為普通載具或步行不退還已消耗的工程車。加油站來源 `41a4db` 對非步行模式使用 `1 << (mode - 1)`，工程車為模式三，費用倍率為四。

以上利用研究 repository 的標記定位，再依擁有者來源與本機反組譯核對語義；沒有把第三方 C／ASM 實作複製進本專案。

## Runtime 與存檔

小型 `game/core/engineering_vehicle.gd` 模組承接載具生命週期與 metadata 規則。GameState 負責階段與玩家檢查、既有土地更新、事件以及回合整合，沿用原有地圖與有限供給模型。

活動工程車以 `vehicle = "engineering"`、`dice_count = 1` 表示，玩家同時有 optional `engineering_vehicle` dictionary：

- `remaining_admissions`：1–7。
- `previous_vehicle`：`walking`、`motorcycle` 或 `car`。
- `previous_dice_count`：先前模式允許的骰數。

非活動時不保留這個 dictionary；既有合法 v13 存檔缺少它時就是未啟用，不需要 migration 或新 marker。工程車不加入普通載具的有限工具總量，也不新增永久的載具擁有權旗標。啟用與到期會維持原機車／汽車的背包、裝備及供給守恆。提前替換、地雷／炸彈清除載具、神明清背包或破產都必須清除期限，避免稍後再次恢復已失效的載具。

住宅拆除會清除樓層與連鎖店標記，設施拆除會同步同一來源物件的全部節點並清除類型／樓層；保留所有權與不相關的既有暫時狀態。研究生產判斷使用拆除後的設施狀態。

## 明確保留的差異

AI 目前只在行動階段的當前成功落點有對手已建成建物時啟用；不以無主建物作為使用動機，也不讓普通載具選擇立刻取消活動工程車。原作精確 AI 閾值尚未確認，這是明確的策略差異。

來源 packed status bits、旅館與其他特殊重新進入流程未建立完整模型，使用現有休養／移動限制；原作工程車造型、動畫、音效與完整節奏尚未重現。遊戲邏輯不依賴原圖尺寸。

驗收位於 `tests/engineering_vehicle_*.gd`；`tools/engineering_vehicle_source_smoke.gd` 可讀既有來源 catalog，驗證兩張地圖的工具使用、落點拆除與 JSON 續玩，不重新匯入整套素材。實際驗證結果記於 PR #51。
