# 卡片、道具與點券

`game/content/original_inventory.gd` 保存兩版共同的 30 張卡片與 13 種道具目錄。
每筆包含原作名稱、1 起算 source ID、初始共享供給量、點券價格及尚未解釋的兩個原始旗標。
既有五種卡片的短名稱 ID 保留，避免僅因顯示名稱改動破壞舊存檔。

## 來源與驗證

直接讀取擁有者本機的兩版 `rich4.exe`，每筆 8 bytes：32-bit 名稱指標，
+4 初始供給量、+5 點券價格、+6／+7 旗標。名稱指標依 PE section 轉為 file offset，
CP950 解碼；Game 卡片表位於 file offset `0x7c152`，道具表 `0x7c242`；
MultiverseJourney 分別 `0x7e3f2`、`0x7e4e2`。Godot 載入目錄後輸出 JSON，
逐筆與兩版二進位表比較 source ID／名稱／供給／價格／旗標：兩版各 43 筆完全相同。

原作說明書 PDF 第 11 頁記載卡片容量 15 張、每類道具最多 9 個。
初始供給並非個人容量：前八種道具的共享供給為 10，後五種為 0；研究道具取得方式另由
原作流程決定，不能僅以表中的 0 推論道具不存在。

研究 repository `mytbk/rich4` commit `54ff26750e7e7f585da6fe68c4e8972cd22ed509`
用於定位資料與流程，再回查擁有者二進位；不複製其 GPL C／ASM 實作。
所有原版執行檔、反組譯輸出及圖像均留本機，不隨程式碼提交。

目錄資料並不代表每張卡片、每種道具的效果已完成。可用時機、共享供給的變動、目標限制、
商店交易與效果必須由 runtime 明確接入；未實作效果不得回報成功或消耗物品。

## 已接入的生命週期核心

`game/core/inventory_rules.gd` 提供一個不依賴遊戲狀態的可重現規則層。呼叫端持有並傳入共享
供給與玩家容器：

```text
supply = {
  "cards": {"均富": 1, ...},
  "tools": {"機器娃娃": 10, ..., "核子飛彈": 0}
}
player_cards = ["均富", "停留"]
player_tools = {"路障": 2}
```

`new_supply()` 依目錄建立完整的卡片與道具供給；`empty_tools()` 建立空的稀疏道具字典。
`initialize_player(player, supply)` 與 `initialize_players(players, supply)` 保留玩家其他欄位，
並把卡片清空、點數設為 0，再各發一個來源 ID 1、2、3、4、8、9 的道具。來源 ID 1–8 的
有限共享供給會按玩家數量扣除；研究道具 ID 9–13 不共用供給上限。初始化會先檢查全部需求，
供給不足時不改動任何玩家或供給。

`grant_card(supply, player_cards, card_id)` 從有限卡片池扣一張並加入玩家；玩家已有 15 張時，
會退回背包中第一張最低點券價格卡片，再把新卡加到陣列尾端。同價時先退回玩家陣列中較早出現
的卡片。`consume_card(supply, player_cards, card_id)` 移除玩家持有的卡片並歸還共享池。
`draw_card(supply, rng)` 是低階的抽取／保留操作：按剩餘供給加權、扣除一張並回傳卡片 ID，
但不寫入玩家背包。需要將抽卡交給玩家時，使用 `receive_random_card(supply, player_cards, rng)`；
它在一個 staged transaction 中完成加權抽取、扣池、滿 15 張時的驅逐與加入，不能再接著呼叫
`grant_card`。

`grant_tool` 與 `consume_tool` 支援正整數數量；每種道具的玩家持有量最多 9。來源 ID 1–8
的發放會扣除共享池，使用後歸還；研究道具 ID 9–13 的發放與使用不改動共享池。數量、ID、
供給或背包格式不合法，以及容量或供給不足時，操作不會部分套用。

`quote_buy(kind, id, quantity)` 回傳目錄標價乘數量；`quote_sale` 則先計算總標價，再截去
`total * 0.9` 的小數。`buy_price`、`sale_price` 是相同計算的短別名；無效項目或數量回傳
`-1`。卡片 ID 與道具 ID 以目錄中的短中文字串為 canonical key，方法也接受 1 起算的
`source_id` 作為查詢／操作輸入。

這一層只處理供給、背包、抽取、容量與點券報價；商店點券結算、存檔版本、可用時機與 UI
由 runtime 接入，詳見下方新局與相容規則。卡片／道具效果另行實作與查證。

## 生命週期驗證依據

兩版執行檔的本機反組譯在 `mj-original-disasm.txt` 的 `4412ae` 路徑以卡片表的價格欄位
（每筆 8 bytes 的 `+5`）尋找第一張最低價卡片；研究程式碼曾標示的 `+7` 回傳位置不是這個
驅逐比較值。MultiverseJourney 的 `406de7` 初始化路徑呼叫來源 ID 1、2、3、4、8、9 的
道具接收；兩版玩家 profile 的點數欄位（`+48`）初始為 0。卡片商店 routine `42d145` 與
道具商店 routine `42d1b2` 使用 `0x464364`／`0x46436c` 的 0.9 常數；Game 版對應
`42c54d`／`42c5b3` 與 `0x462350`／`0x462358`。以上只記錄本機執行檔的觀察結果，沒有
複製研究 repository 的 GPL C／ASM 實作。

## 新局與相容規則

新 UI 開局明確傳入 `original_inventory: true`，使用 v4 存檔與共享供給。
未指定此選項的 API 呼叫，以及既有 v1／v2／v3 遊局，保留原規則；從舊局重新開始也保留
該局的模式。JSON 與磁碟讀檔會把合法整數值正規化，並檢查卡片總量、前八種有限道具總量
與目錄相符。研究道具的共享池固定為零，每位玩家仍受每類九個的上限約束。

卡片格的領卡、商店買賣與使用後回池由 runtime 接入。新模式可在擲骰前或行動階段使用
可執行的卡片，選路中不能使用；未還原效果會拒絕並保留卡片。商店由來源節點 `event_code=15`
及實際停留的行動階段識別，保留既有 map classification／存檔格式相容；經過時不開店。
一般商店目前販售卡片與來源 ID 1–8 道具，研究道具取得方式仍待另行接入。

背包與商店介面呈現點券、持有量、剩餘庫存、價格和數量報價。滿十五張手牌時不能再從商店
購買；卡片格強制取得新卡時則採原作的最低價驅逐。新模式停止現金買車，交通工具從道具
背包中裝備；裝備後可調整骰子數或改為步行，切換時退回原載具。破產玩家目前保留 held
inventory 與裝備以維持供給總量；原作退場物品回收時機仍待查證，
不可把這個暫定保留策略宣稱為原作還原。

## 常用效果查證

以下是 MultiverseJourney 原始 EXE 的觀察，作為效果實作依據，不代表所有列出的效果均已接入。
機車 ID5 的效果 routine 為 `0x446e4a`，汽車 ID6 為 `0x446f05`；
使用會切換為最多兩顆／三顆骰子，並把原載具退回玩家背包、從背包扣除新載具。
兩個 routine 都直接增減 `player_id * 15 + 0x499160/0x499161`，不是共享池。
載具仍在裝備中時不是消耗性工具，
必須納入有限供給的總量，不能把背包扣除誤當成歸還共享池。

遙控骰子 ID8 `0x4470f8` 的人類選擇 callback `0x446774` 建立六列 1–6 的選項，
成功才扣除工具並寫入選值；取消不扣除。`0x447285` 讀取並清除待用值，移動流程
`0x40d9a4` 把它交給 `0x419572`；非零時該函式強制一顆骰子並使用所選值，因此不是
汽車三顆骰子各自套用同一點數。AI 原作選值分布尚未確認。
轉向卡 `0x442f4d` 成功後呼叫 `0x40c78c`，使目標玩家方向反轉 180°，並從目前節點的
合法鄰居中排除舊 previous node，再隨機選一個寫入 previous；沒有候選時寫 source 的零 sentinel。
卡片本身不移動玩家。均貧卡 `0x4421b4` 只選對手，
雙方現金設為整數平均。通用 selector 的精確數值距離仍未確認，不能宣稱目前全地圖玩家列表
已還原原作的距離限制。

路障 `0x446baa` 以 `0x40e033(type=0x10)` 放置後扣除工具。原作手冊 p.29 要求目前可見、
無玩家停留的道路，移動遇到路障停止並移除；精確數值距離尚未解碼。
`0x445aa2` 扣除玩家持有數，來源 ID ≤8 時同步加回共享池。因此已放置路障不再計入背包
供給守恆，移除路障也不能再次歸還共享池。購地卡 `0x442325`
處理目前節點的土地／設施並檢查所有權與現金，公司不在該分支內。拆除卡 `0x443b0f` 對
土地／設施降一級，對道路物件移除；工人 `0x447295` 對普通建築升級至最多五級、連鎖店一次，
此 routine 本身沒有價格檢查。設施專屬上限、公司與道路物件的完整生命週期仍需各自接入。

紅／黑卡的原始 `0x429040` 寫入 stock event delta 的常數是 `0x41200000`／`0xc1200000`
（float +10／−10），再以 `0x428ec5` 的基準價與隨機插值計算價格。先前 +8 的研究線索已由
本機 EXE 否定。狀態在市場 tick 前衰減（紅 `0x20→0x10→0`、黑 `2→1→0`），不是每日
固定重複乘 ±10%；原版 UI 日數邊界仍未核對。目前既有股票與紅／黑卡保留暫定模型，不能
宣稱這部分已還原。免費卡 `0x444a60` 則由付款前的確認／取消流程觸發，成功才扣卡並讓
呼叫端把應付額設零；尚未接入的付款選擇不能用無條件主動施放取代。

## 本票已接入的住宅與道路效果

路障目標由 UI 的目前可見節點與核心合法目標取交集。原作 `0x445e4d` selector 的
`0x40aa0f` helper 檢查相鄰邊及 `status_bits & 0x80ffff00`，低位 event byte
本身不排除目標；可在無玩家停留的合法事件節點放置。`0x40e033` 為 type `0x10`
配置 `[0x10, 0x1a)` 十個槽，runtime 因而限制同時最多十個路障。撞上後移除並截停
剩餘步數，再處理該格正常停留事件。UI 使用獨立向量標記，不把原圖尺寸寫入遊戲狀態。

購地卡目前處理腳下普通住宅，以現有土地動態價格扣除買家現金；有主住宅將款項記入
原屋主存款，同步調整銀行與雙方資產／所有權。拆除卡可使指定普通住宅降低一級，或清除
指定路障；機器工人可使指定已持有的普通住宅免費升一級，最高五級。人類可以指定對手
住宅使用工人；AI 僅替自己升級。非法目標、資金或上限不足均在消耗物品前拒絕。
設施／連鎖店另由 #18 處理，未在此宣稱已實作。

v4 保存 `roadblocks`（canonical 十進位節點字串 → 放置者 ID）；載入檢查節點、
可達性、佔用、數量及放置者格式。v1–v3 保留舊模式，非圖形 v4 只允許空路障。
