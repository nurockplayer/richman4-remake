# 監獄入口、醫院入口與魔法屋：原版靜態研究

本文件只記錄 owner 提供的兩個原版 PE 靜態反組譯；未執行原版，未提交執行檔或素材。下列位址預設為 MultiverseJourney；Game 位址另列。未追完的路徑明記 unknown，不能當成完整實作契約。

## 規則

### 4 監獄入口、5 醫院入口

這兩格不是把落地者送進監獄或醫院。各自先查八個設施名冊槽；名冊全空則直接返回。有名冊時，真人開啟設施視窗；AI 可能付點券讓名冊中的人或其他對象提早釋放。監獄與醫院分別使用獨立名冊和狀態欄位。真人視窗只列出非空槽：0–3 為四位玩家、每位 30 點券；4–7 依序為小偷、強盜、流氓、間諜、每位 300 點券。點選後檢查點券至少等於價錢並要求確認；拒絕確認不扣點，點券不足顯示提示。右鍵可離開；醫院在對象列表以外的播報階段右鍵先快轉，回到列表再離開。一次成功後視窗結束。沒有「自動救落地者」效果：落地者只有在自己的槽非空且被選時才受上述規則影響，而一般拘留中的玩家無法正常進入落點處理。空名冊不開視窗、不扣點、不改狀態；共同 dispatcher 的事件音效呼叫在此之前。

AI 先抽一次，低位為 0 即離開；為 1 才依玩家 `+0x17` 策略位元組建候選：值 0 取名冊槽 0–3，值 2 取 4–7；值 1 先取 0–3，再抽一次 `rand % 3`，餘數 0 時也納入 4–7。候選空則離開，否則再抽 `rand % 候選數` 選一項。槽 0–3 價格各 30 點券，要求點券 **嚴格大於** 30；槽 4–7 價格各 300，要求點券至少 700。選到不可負擔的項目直接離開，不重抽。成功扣價；前四槽將對應玩家監禁／住院狀態設 `0x80` 並清除名冊槽，後四槽呼叫釋放 helper。4–7 是與玩家分開的四個 NPC 固定槽；送入 `43d593`／`43ec3f` 以 NPC ID 4–7 設槽、移除其道路佔位並清除行動欄位。玩家破產時 `40ce86–40cef3` 會把其仍在路上的小偷、強盜送監獄，把流氓、間諜送醫院；這是已證實的入所路徑，不宣稱是唯一原因。釋放 NPC 時設定其僱主為落地者、移到設施位置、設置狀態及方向旗標，然後清除槽；NPC 回到地圖，並非給落地者直接入獄或住院。真人救玩家還會經 `40df69` 降低被救者對落地者的敵意，AI 入口路徑沒有這次呼叫。

### 16 魔法屋

魔法屋先決定一組受影響者，再決定同一效果並依序套用到組內玩家；可能包含落地者，也可能有多人。受影響組的 12 個候選是：財產、土地、房屋、現金、存款、點券各自最多的人（含並列），走路、騎機車、開汽車、神明附身的人，以及所有男生、所有女生。選組以 `rand % 12` 反覆抽到有合格目標為止；因此各次餘數並非絕對均勻，最終分布也依當局合格組而變。具體條件及零值處理見下方「目標組」。

真人介面顯示抽中的組並讓玩家從 12 個效果自由選一個；第 13 個命中區回到選擇階段，不是免除效果。右鍵在早期階段快轉播報，選擇階段右鍵不退出；未找到免除或取消效果的正常路徑。AI 若抽中組包含自身，選效果 6（得一張卡片）；否則抽 `rand % 11`，餘數 6 改為 7。故條件於該 AI 分支，效果 0–5、8–9 各為 2979/32768，效果 10 為 2978/32768，效果 7 為 5958/32768，效果 6 與 11 為 0。這是精確取模計數：32768 = 11×2978 + 10；若組含自身，效果 6 為確定選擇。

## 目標組

`431842` 每組先遍歷參與玩家 `0..499114-1`，只收 `+0x15 != 0` 者；破產時 `40ce13` 清零此欄，故破產者排除。這裡沒有住院／入獄欄位排除：仍存活且被拘留的玩家可入組，之後各效果仍有自己的狀態 gate。每組不選任何人就重抽；所有並列最高者都入組，依玩家索引順序。

| 組 | 來源實際條件 |
| --- | --- |
| 財產最多 | `4239b9` 計算現金＋存款－負債、股票及房地產等淨資產，最高值初始為 0；零值可並列，若全為負值則空組 |
| 土地最多 | 統計住宅和設施 owner 為玩家的筆數，須大於零 |
| 房屋最多 | 同上但僅計建築等級非零的筆數，須大於零 |
| 現金／存款／點券最多 | 各取對應欄位的非零值最高者；全為零則空組 |
| 走路／機車／汽車 | 載具 byte `+0x11 & 3` 分別等於 0／1／2；值 3 不屬於這三組 |
| 神明附身 | `+0x3f != 0` |
| 所有男生／女生 | 性別 byte `+0x14 != 0`／`== 0` |

## 來源與 RNG 證據

落點 dispatcher 在 `4198b2` 以 event code 索引 `4197e9`：4 → `41b132` → `43d304`；5 → `41b13c` → `43e9a4`；16 → `41b3cb` → `43380a`。Game 的表為 `418f82`、跳轉 `41904b`：4 → `41a9b9` → `43c03f`；5 → `41a9c3` → `43d6c0`；16 → `41ac52` → `432bb7`。Game 的三個 entry 已定位，但其 helper、資料表和完整行為尚未逐分支與 MultiverseJourney 比對，因此版本等同性 unknown。

共同 dispatcher 在 `41986c–41987e` 檢查當前玩家 `+0x37`；非零且事件非零時跳到返回。這與睡夢 gate 的既有語意相符，但此處未獨立證明每個非零值的名稱。事件 2–16 先呼叫 `4542ce`，再進 jump table；其內部是否消耗亂數 unknown。移動路徑在 `40d947–40d960` 對剩餘步數 `48baf8` 非零時呼叫 `40c05c` 前進並遞減；`418e7f → 41982d` 是落點事件 dispatcher。另在 `40d82a–40d889` 的 `498ea5` 是移動狀態用計時欄位，不能當成剩餘步數；事件 handler 的直接呼叫點僅位於該落點表。經過 4／5／16 不進這三個服務 handler。另一個 caller `418d88` 是回合 dispatcher 的落點分支。移動過程仍有獨立的通用道路、障礙與其他格子處理；不能以此宣稱所有經過都沒有任何通用副作用。載具是否對入口有額外 gate、入口是否受神明修改亦 unknown。

入口 AI 的亂數呼叫依序見監獄 `43d3d8`、可選 `43d44f`、`43d4ac`；醫院 `43ea84`、可選 `43eafb`、`43eb58`。兩個視窗分別載入資源 ID `0x3f/0x40`、`0x41/0x40`，callbacks `43caab`、`43da27`；名冊分別是 `496b30`、`496b60`，玩家陣列 stride `0x68`、基址 `496b68`，點券 `+0x30`、監獄 `+0x34`、醫院 `+0x35`。依賴的目前玩家索引是 `49910c`。

魔法屋 `43380a` 使用資源 `0x12/0x13/0x14`，真人 callback `4325c2`；`432719–43273f` 抽目標組並以 `431842` 驗證，真人之後選效果，進入 `431caa`。AI 的目標組循環在 `433910–433932`，效果抽選在 `433966–43397e`；`431c7a` 是效果表，`475724` 是效果文字表，`4756b8` 是目標組文字表，`48c380` 保存目標玩家列表。真人動畫 callback `432a85` 等另有 RNG 呼叫，呼叫次數受 UI 時序影響；效果 helper 本身也可能抽亂數，總數 unknown。

`456f2d` 每次更新 LCG 狀態並回傳高位的 15-bit 值。上述取模與 Godot `game/core/game_state.gd` 的 `_rng.randi_range` 不是相同序列或同樣偏差；若要重製分布及存讀一致性，需另行決定相容策略，不能宣稱直接對應。除明列呼叫，UI、helper、前後落點工作之完整 RNG 順序 unknown。
