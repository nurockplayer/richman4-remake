# 房產交換卡

Issue #35 接通換地與換屋。完整原作圖的新局明確啟用
`original_property_cards`，以 v10 保存；v1–v9 不會因載入新版程式而新增這兩張卡的效果。
後續 v11 的改建模式保留兩種交換，並延伸住宅連鎖店交換，見 `original-remodel.md`。
有限卡池、背包容量與成功消耗後回池沿用既有規則。

## 已核對的效果

兩張卡都以玩家腳下的住宅或商業設施為起點，選擇畫面可見的另一處同類地產。
住宅只能對住宅，設施只能對設施；公司、道路及同一物件的另一入口都不是合法目標。
不要求地產必須屬於施術者，也不排除同一屋主、第三方、無主、零級或同等級的目標。
合法但沒有淨效果的交換仍消耗卡片。取消、無卡或非法目標先拒絕，不改動棋局。

| 卡片 | 交換內容 | 留在原址的資料 |
| --- | --- | --- |
| 換地 | 兩處所有權與玩家房產參照 | 建物、設施類型、臨時狀態、價格、座標 |
| 換屋 | 普通住宅等級；商業設施類型與等級 | 所有權、臨時狀態、價格、座標 |

成功沒有現金或存款費用。交換後同步設施的所有入口、房產估值、住宅租金與可用操作，
但不重新觸發停留收費。UI 的可見目標由核心合法集合與當前地圖視窗取交集；
畫面內沒有目標時停用出牌，關閉背包再平移地圖可以重新選擇。

## 來源

依據擁有者 private Git/LFS source 中的 MultiverseJourney `rich4.exe` 與手冊實體
p.23–24。研究 repository 只作定位，再回查擁有者的二進位；不複製 GPL C／ASM 實作，
也不將原始或衍生素材放入 public code repo。

- 換地 `442622..442b01`：住宅與設施使用 selector `0xe0c0202`／`0xe0c0204`；
  `4427bb`／`442a09` 只交換紀錄 `+0x19` 所有權，成功尾端消耗卡 ID4。
- 共用 selector `44639a..44642f` 要求同類且不同來源物件，沒有所有權限制。
  手冊則明示地圖視窗範圍。
- 換屋 `442b02..442f4c` 呼叫 `40b4f8`；`40b6c5..40b6da`／`40b89e..40b8b3`
  交換 `+0x1a` 等級與 `+0x18` 建物類型，不交換 `+0x19` 所有權或 `+0x1c` 臨時狀態。
  helper 先保存座標，動畫結束後寫回原值；不能把這個還原過程解讀為交換地理座標。
  成功尾端 `442f2d..442f3e` 消耗卡 ID5。

## 尚未宣稱還原的部分

原作住宅的 `+0x18` 也代表連鎖店旗標，換屋會連同它交換。目前十二張來源圖的初始旗標
均為零。v10 只處理可生成的普通住宅；v11 隨改建與連鎖店系統接入旗標／等級交換，
v10 舊局仍保留原規則。研究所生產及原版動畫等剩餘差異另見 `original-remodel.md`。

AI 採可重現的效益策略，只在找到有利的合法交換時使用卡片。這是本重製的策略，
不是已核對的原作 AI 目標排序。原版交換動畫也尚未接入；這些差異不擴張本票的驗收範圍。

## 驗證

`bash tools/check.sh` 包含房產卡流程、存檔、AI、UI 與來源能力檢查。合成 fixture
覆蓋無主、同主、第三方、設施多入口、取消及非法目標不變性，並保留 v1–v9 相容檢查。

已有擁有者授權的完整來源目錄時，可另外執行：

```sh
godot --headless --path . --script tools/property_card_source_smoke.gd -- "$RICHMAN4_MAP_CATALOG"
```

此驗證在十二張來源圖各進行四名 AI 的三十天遊局，每回合檢查存檔並從 JSON 重載後
比較續玩；輸出實際交換次數，不把單純持有卡片當成效果已執行。來源素材仍從既有
FULL 驗證目錄讀取，不要求為每個實作 worktree 複製素材或匯入快取。
