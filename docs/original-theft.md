# 搶奪卡

[Issue #64](https://github.com/nurockplayer/richman4-remake/issues/64) 接通既有目錄中的搶奪卡，沿用目前原版背包與存檔模型，沒有新增版本或舊開發語意分支。

人類在背包先選畫面內存活的其他玩家，再選其持有的一張卡片或一個道具；裝備中的載具不列入背包選項。確認時核心重新驗證目標、持有量與使用時機。取消、失效目標與非法物品不改變狀態或 RNG。原版精確選取距離與 AI 評分仍未確認；畫面可見範圍沿用既有目標介面，AI 使用固定順序的點券價格優先策略，並避開自己已滿的工具。

本機 MultiverseJourney EXE 的 `443e3d` 搶奪入口呼叫 `44192a` 選取與移轉。`4413ec` 讀取目標的卡片格，`447c6e` 建立正數工具的列表；第二區只在 mode=1 開放。確認後由 `441ab9` 分成卡片與工具兩路：先扣目標、再嘗試接收，最後才消耗搶奪卡。右鍵取消或沒有有效選擇時回傳零，不移轉物品。GPL research repository 僅用於定位，沒有複製其實作。

已確認的容量特例保留：

- 工具已達九個時，目標仍少一個、使用者不增加，且搶奪卡消耗。有限工具回共享池，研究工具消失。UI 明示「持有已滿」，不把這條來源行為改成拒絕操作。
- 手牌已有十五張時，先按既有最低點券價格規則驅逐一張，再收取目標卡。若搶奪卡本身最便宜而先被驅逐，最後不重複扣除；否則再消耗一張搶奪卡。來源見 `4412e4` 與 `443f37`。

數量、有限供給、完整 JSON 與 AI 回放由 focused tests 驗證；真實背包操作由 `tests/theft_ui.gd` 驗證。實際執行與候選版本證據記於 active PR。
