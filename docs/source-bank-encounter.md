# 原版銀行進出流程（#135）

來源為擁有者授權的目標版本程式與 Panel21／23／24 素材。原始與衍生素材不進公開 Git；素材座標與外觀契約沿用 `source-bank-panel.md`。

## 玩家流程與模擬邊界

`rich4_player_core_actions.asm` 的 2548–2559 行先執行落點 ATM，再進銀行；2683–2728 行在經過銀行時同步開啟 ATM，關閉後才執行同一格後續效果與剩餘移動。`rich4_ui_bank.asm` 的 3490–3561 行限制商業銀行後台為當前擁有者，AI 另走不開人類視窗的分支。

原本核心記下 `bank_passed` 後立即繼續移動；只在動畫結束後補彈窗會讓交易晚於費用、神明或障礙物。新的小型 `bank_visit.gd` 模組保留必要的模擬決策：

- 經過銀行且仍有步數時，保留 `pending_movement`，進入 `await_bank`。`pending_bank_visit` 只有 `kind`、`player_id`、`node_id` 三欄；此時只允許存款與提款。
- 關閉 ATM 後，`resume_bank_visit()` 先處理已抵達格的未執行效果，再繼續移動。已完成的移動與銀行事件不重播；附身神明的座標先跟隨玩家，效果仍等待交易完成。
- 最終停在銀行時，只建立一次 `landing` 決策，依序顯示 ATM、銀行前台；商業銀行擁有者可進後台。前台退出透過 `complete_bank_visit()` 恢復通常行動。
- 決策中的非銀行操作、錯誤金額與過期續行都不修改模擬或 RNG。星期日、AI、睡眠、住院／坐牢及既有待回應事件不進此人類流程。既有新聞貸款封鎖只禁止新貸款。

待處理銀行決策可序列化並以 JSON 還原，續行結果相同。驗證器拒絕錯誤欄位型別、其他玩家／格子、階段孤兒、衝突事件與不合法的移動狀態；不依靠執行期例外拒絕資料。沒有新增舊開發存檔 migration 分支。

## 呈現接線

`source_bank_controller.gd` 位於原版 reference canvas，接收核心的公開決策、交易上限、公司擁有者與帳戶摘要。提款／借款與關閉續行均經過 MainUI 既有結果及移動呈現介面。金額不因無關刷新而清空；拒絕訊息在同步刷新後仍可見；更換遊戲會取消舊的延後回呼。

ATM 邏輯位置為 `(60,71)`、尺寸 `320×338`；前後台使用 `640×480` reference canvas。銀行決策封鎖棋盤、股票、存讀檔、新局與 AI 操作，直到正確續行或結束。畫面狀態不持有必要的模擬資料。

## 驗證與限制

先提交的核心行為測試 `8497687` 為 56 項／14 個失敗、0 個 setup failure；控制器主機測試 `4632dfd` 為 36／19；同格效果測試 `41dff47` 為 93／6；型別測試 `94080e3` 為 83／4，另觀察到正式驗證器的執行期錯誤。修復後核心 402、效果 126、型別 83、控制器 33、主機 37、MainUI 25 項全數通過。原有銀行元件與會計測試保留。

測試工具修正另行提交：`64c1d10` 在提款後重新設定零現金拒絕案例；`7f56e2a` 排除更換核心本身的摘要查詢；`506cae7` 修正四步地面物件 fixture，並明確驗證路障停止後合法的新落點決策及重複續行拒絕。這些修改不代替正式程式修復證據。

原生圖形測試使用隔離 SubViewport、安靜音效與合成或明確提供的 catalog，不修改擁有者存檔。實際 catalog 的正常入口另由 `source_bank_catalog.gd` 驗證：Game:3 的 seed 4、MultiverseJourney:7 的 seed 6，從公開新局工廠與擲骰／選路進入 ATM，再到前台並返回棋盤；不注入位置、銀行決策或完整能力 fixture。58 項檢查在 headless 與原生圖形模式皆通過；未提供 catalog 時明確 SKIP。整批核心／schema 更動另通過完整 `tools/check.sh`（197 次 Godot 執行、82 個 Python 測試，沒有 Godot 錯誤），之後只增加實際 catalog 測試及 runner。

程式、隔離圖形與實際 catalog 證據不等同作業系統實體輸入或完整新套件驗收；S11–S13 與 Mission 必須等逐幕原版對照、獨立審查與整合 gate。

實際地圖前台畫面另揭露原本隔離黑底未顯出的合成問題：UI atlas 的零色值透明像素會透出棋盤。原作 `rich4_ui_bank.asm:876` 經 `rich4_drawing_utils2.asm:338` 呼叫整塊影像複製，包含零色值；因此前後台來源背景補上不透明黑底，sprite atlas 的透明度維持原樣。先提交的 `6f3b499` 原生回歸案例，在兩版前後台、藍／綠底板間重現 16 項／8 個失敗；所有來源影像有效性檢查先通過。修復後原生像素案例必須全數通過，headless 明示 SKIP，不冒充像素驗證。
