# 銀行貸款與提前還款

原版公司模式使用 `bank_loan_limit("take_loan" | "repay_loan", player_id)` 查詢可用金額，再由既有 `choose_action` 入口處理正整數金額。查詢只提供資金上限；銀行位置、週日、階段、拘留與新聞等 gate 仍由正式行動入口判定。新聞禁止新借款時仍可提前還款。既有三股示範模式維持原來的貸款流程，沒有新增存檔能力標記或版本。

來源 `rich4_ui_bank.asm:3499–3505,2023–2042` 以進入銀行時的淨資產減現有本金作新增借款上限，款項進入存款。借款、存提款及還款不改淨資產，因此同一銀行操作期間可由目前資產重算剩餘額度。沿用既有 `_player_wealth` 的資產估值。

`:193–226` 僅在到期日為零時建立 90 天期限，休息日順延，續借不延期。已確認 `rich4.asm:27414–27454` 的 Sunday 關閉規則；各地圖節日表尚未映射，保留現有只判定週日的政策，不能聲稱完整還原假日。`:2104–2139` 的部分提前還款先扣存款、再扣現金；清償全部本金才清除到期日。到期自動處理維持現有 `end_turn` 時序並使用同一扣款順序，資金不足仍進既有破產處理。

重製版保留銀行帳務：借款增加存款負債與貸款資產；存款還款同額減少兩者；只有現金還款增加銀行現金。各欄位遵守既有 `10^12` 上限。極端的銀行現金飽和狀態會限制可收現金；到期時先收可入帳金額，保留未清本金與原期限，後續回合再處理，不因銀行上限宣告有支付能力的玩家破產。這是維護既有存檔數值邊界的最小偏離。

`tests/source_loans.gd` 在實作前提交，透過合法銀行 fixture 的公開行動確認貸款、部分／全部還款、輸入拒絕、額度、期限、週日、JSON 及後續 RNG；不讀寫玩家資料。原始 RED 另包含 `choose_action` 把 Dictionary／Array 強制轉成 `int` 的產品例外；不是 fixture 建立或測試解析失敗。特殊融資是獨立來源範圍，未在此變更實作。核心通過不代表 S12 畫面或整體 Mission 驗收。
