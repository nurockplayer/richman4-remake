# Source bank-chair financing

Issue #124 / parent #102 S13. In company mode, a type7 company is a bank. Normal banking uses the existing Sunday, phase and player-status gates. Only the owner of the bank currently entered can take or voluntarily repay special financing; the news borrowing restriction blocks new financing and preserves repayment.

The primary source `rich4_ui_bank.asm:980–1004,1081–1140` sets new credit to other player deposits less the outstanding special principal. Borrowing increases `deposit` and optional `special_finance`; it does not change cash, normal loan or its due date. Repayment uses deposits before cash. `rich4_calculate_player_wealth.asm:20–26` subtracts only the normal loan: special financing therefore increases source wealth. This deliberate original oddity supersedes a contradictory secondary description.

Source settlement hooks are bounded to the confirmed calls: manual withdrawal (including the existing ATM path if it reaches the same public withdrawal operation) checks the last owned type7 bank's chair, excluding a withdrawal by that chair. It collects the difference when other active players' deposits fall below the outstanding principal. Company ownership reconciliation collects all financing from players who are no longer that last bank chair. Insolvency uses the existing bankruptcy cleanup; clearing special principal before stock disposal prevents reentrant collection. Other deposit spending does not gain an invented global callback. A separate ATM tool presentation remains unimplemented.

The menu counts other player slots regardless of alive status; forced capacity uses active players, preserving the source distinction. The bank deposit/cash mirror follows the remake accounting model. Special financing does not create ordinary `bank.loans` assets. Existing 10^12 save bounds limit issuance and cash repayment. At a saturated bank cash counter, a solvent forced debtor's unpaid remainder is deferred to the next source reconciliation instead of overflowing or causing artificial bankruptcy; this is the minimal numeric-bound deviation.

There is no new save version or capability. Missing player metadata means no financing used; present metadata must be an integral value in range, in company mode, and zero for bankrupt players. No player save is migrated or replaced by the implementation. UI wiring, original/remake rendering and ordinary native/package gates remain unaccepted.
